| HIGH | `src/zrb_llm_evaluator/runner.py:36-39` | `_log()` helper uses `print()` in library code — violates RULE-011 ("Library code MUST NOT use `print()`"). Code is NOT in `HEAD`; it ships in the PR's diff. Action: either relocate logging to the CLI entry point (`cli.py`) or use `logging`. Ruff `T201` (flake8-print) will fail CI. |

The refactor ships in the same diff as the workdir-isolation work. Leaving them red blocks RULE-007 coverage gate verification. |

## Verdict

**REQUEST CHANGES**

The workdir-isolation REQs (020–024) are themselves correctly implemented, well-traced, and covered by 6 passing tests. However, the same PR ships:
1. A hard RULE-011 violation (`print()` in library code at `runner.py:36-39`) plus the corresponding RULE-009 (clean-ruff) failure;
2. Three failing pre-existing tests caused by an in-scope `communicate → wait` refactor that bundled in.

Both must be resolved before merge. The LOW/MED findings are nice-to-have cleanups that can be addressed in the same fix pass.
