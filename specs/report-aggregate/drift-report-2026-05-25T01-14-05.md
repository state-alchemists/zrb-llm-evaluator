REQ-030..REQ-042 each map cleanly to a code location and are exercised by `tests/report-aggregate/test_reporter_aggregate.py` (UT-A001..UT-A025) and `tests/report-aggregate/test_integration_aggregate.py` (IT-A001). No `REMOVED-from-code` items were found.

Two minor drift items did surface — both about the spec's claims being looser than the code's actual guarantees, not about behavioural mismatch:

1. **NFR-002 says "O(T) with a single pass per section"** — the code adds `sorted(...)` calls per section, so it is O(T log T) overall. The *intent* ("no quadratic blow-up") is preserved.
2. **NFR-004 only promises byte-equal aggregate region** — the code actually delivers a byte-equal *entire file* across re-renders, because the header's `**Generated**` timestamp is derived from `experiment.completed_at or experiment.started_at`, not `datetime.now()` (`reporter.py:379`).

The user chose **Overwrite — apply both changes** in Phase 6. NFR-002 was relaxed; REQ-043 was added.

### Modified — was / now
- **NFR-002**
  - was: *"Aggregate rendering must be O(T) in the number of trials with a single pass per section."*
  - now: *"Aggregate rendering must avoid super-linear blow-up in the number of trials: a single O(T) collection pass over `Experiment.results` plus per-section sorting whose total cost stays within O(T log T)."*
  - Reason: `_render_by_model`, `_render_by_test_case`, `_render_grid` (axis sort), and `_render_failing` all call `sorted(...)`, contributing an `O(M log M)` / `O(C log C)` / `O(F log F)` factor where M, C, F ≤ T. The collection pass itself remains O(T). The prose "no quadratic blow-up" was always the intent and is unchanged.
  - Tests: UT-A023 already exercises a 1000-trial fixture under a wall-clock budget and remains valid against the relaxed bound.

### Added
- **REQ-043** (Invariants section): *"ALWAYS SHALL repeated calls to `generate_markdown_report` on the same `Experiment` instance produce byte-identical output across the entire file (not only the aggregate region); to make this hold the `**Generated**` timestamp in the report header SHALL be derived from `experiment.completed_at or experiment.started_at`, not from wall-clock time."*
  - Source: `reporter.py:379` — `generated_at = experiment.completed_at or experiment.started_at`.
  - Why this is a strict strengthening of NFR-004: NFR-004 (and REQ-034) only assert byte-equality of the *aggregate region*; the code's behaviour guarantees the whole file (header + aggregates + Summary + Per-Trial Details) is byte-equal across re-renders. The contract should match.
  - Current test coverage gap: UT-A005 asserts the region only. A whole-file equivalent test would close the gap (suggested next step: `/sdlc-test-plan report-aggregate`).

## Observations (not promoted to REQ-*)

These were considered but deliberately left out of the formal requirement set:

- **`_render_grid` separator width adapts to header length** (`reporter.py:279`: `"-" * max(3, len(col))`). All other renderers use fixed-width separators. This is a Markdown-rendering nicety, not a contract — neither tests nor users depend on the exact dash count.
- **Blank line `\n` precedes each section header** (`"\n## Overall Status\n\n"` etc.). Consistent throughout; implementation detail of how the renderers' lists are concatenated. Not a contract worth pinning.
- **`_status_cell` falls back to bare status text** when an icon isn't in `_STATUS_ICONS`. Already documented in design.md's Validation section as a defensive path. No need for an EARS statement on top of the design prose.
- **`_StatusCounts` and `_AggregateBuckets` dataclass shapes** — already enumerated in design.md's API Surface table.
