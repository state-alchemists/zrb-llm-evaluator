## Observations (not promoted to REQ-*)

These were considered but deliberately left out of the formal requirement set because they read as implementation choices, not contracts:

- `cli._setup_logging` configures a stderr handler with `[%(asctime)s] %(message)s`. Useful for observability but not a behavioural contract.
- `loader._import_validator` derives a unique `sys.modules` name per test case so duplicate `validator.py` files don't collide. Defensive coding, not user-observable.
- `runner.WorkSteward._run_one` emits `START` / `DONE` log lines with `(done/total)` counts. Cosmetic.
- The `Report` Pydantic model returned by report generators is described in the entity dictionary; capturing it as a separate REQ would duplicate that.
