## 0.1.5 — 2026-05-22

### Added
- New test `UT-043` (`test_timeout_kills_whole_process_group`) verifying that on timeout the entire descendant process group is killed via `os.killpg` with `SIGKILL` and that `create_subprocess_exec` is called with `start_new_session=True`.
- Quickfix specification document (`quickfix-2026-05-21T15-03-46.md`) describing the process-group kill behaviour change and its rationale.

### Changed
- **REQ-005**: timeout handling now kills the subprocess **and its entire descendant process group** instead of only the direct child. The trial subprocess is launched with `start_new_session=True` so it becomes its own process-group leader; on timeout the runner calls `os.killpg(os.getpgid(proc.pid), signal.SIGKILL)` to reap all grandchildren (e.g. LLM HTTP workers spawned by `zrb chat`) along with the leader, releasing parallelism slots promptly and ensuring the TIMEOUT recorded in `results.json` matches reality.
- Existing timeout tests (`UT-005`, `UT-009`, integration tests) updated to mock `os.getpgid`/`os.killpg` and expose a `pid` attribute on the mock process, keeping them green under the new mechanism.

### Fixed
- Orphaned grandchild processes after a trial timeout no longer linger for tens of minutes, hold semaphore slots, or mutate `cell_dir/workdir/` files after the runner has moved on. Idempotency on resume is restored.
