## 0.1.3 — 2026-05-21

### Added
- Markdown report now sorts trial rows by `(model, test_case, trial_index)` ascending for stable, diffable output (REQ-025, AC-010, US-009)
- Best-metric bolding: per test case, the minimum `duration`, maximum `score`, minimum `total_tokens`, and minimum `tool_call_count` among `PASS`/`EXCELLENT` trials are rendered in Markdown bold; ties bold all matching cells; `FAIL`/`TIMEOUT`/`ERROR` trials are excluded from computation and never bolded (REQ-026, REQ-028, AC-011, US-009)
- Status icons: each status cell is prefixed with a Unicode emoji — `EXCELLENT` → 👍, `PASS` → ✅, `FAIL` → ❌, `TIMEOUT` → ⏱️, `ERROR` → ⚠️ (REQ-029, AC-012, US-009)
- Pure Markdown output: report uses only Markdown syntax with no embedded HTML (REQ-027, AC-012)
- Deterministic report generation: repeated rendering of the same experiment produces byte-identical `report.md` (UT-042)
- ADR-8 documenting Markdown report rendering conventions
- Comprehensive test suite for report rendering: 11 unit tests (UT-032–UT-042), 1 integration test (IT-006), and 1 end-to-end test (E2E-004) covering sort order, bold scope, status icons, no-HTML enforcement, and deterministic output
- Updated problem brief with US-009 and acceptance criteria AC-010–AC-012
- Updated design spec with report rendering section per ADR-8
- Updated test plan with new test cases and property coverage

### Changed
- `reporter.py` — refactored `generate_markdown_report` to implement sorted rows, per-test-case best-metric bolding, status icons, pure Markdown output, and deterministic generation timestamp derived from experiment metadata
- `pyproject.toml` — version bumped to 0.1.3; `typer` dependency updated from `>=0.15` to `>=0.21`
- `docs/architecture.md` — added ADR-8 to the ADR table
