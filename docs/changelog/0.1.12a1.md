## 0.1.12a1 — 2026-05-27

### Added
- `TrialTrace` and `ToolCallRecord` Pydantic models exposing structured session history (tool calls, assistant text, turn count) to validators
- `build_trial_trace()` function in cost parser to parse session history JSON into a `TrialTrace`, tolerant of missing or malformed files
- `_extract_tool_names()` function supporting pydantic-ai `parts[]` shape with multiple parallel tool calls per message (replaces single-name `_extract_tool_name()`)
- `_coerce_tool_args()` helper to normalise tool-call arguments from JSON-encoded string or already-decoded dict
- Optional `trace: TrialTrace | None` parameter to `ValidatorProtocol.validate()`, enabling trajectory-aware validators while maintaining backwards compatibility
- Stability section in the markdown report (`_render_stability()`) with 🟢 STABLE / 🟡 FLAKY / 🔴 BROKEN classification per (model, test_case) cell; suppressed when every cell has a single trial
- `WorkSteward` class for bounded-concurrency parallel trial execution
- `_load_or_init_experiment()` function for experiment lifecycle management with corrupt-JSON fallback
- Custom `env_prefix` support — environment variables use the configured prefix (e.g. `MYAPP_LLM_HISTORY_DIR`) instead of the default `ZRB_LLM_*`
- CLI `report` subcommand with error handling for corrupt `experiment.json`
- CLI `list` subcommand to display model names from `results.json`
- Evaluator design specification (`specs/evaluator/design.md`), requirements (`specs/evaluator/requirements.md`), and quickfix document (`specs/evaluator/quickfix-2026-05-27T06-26-31.md`)
- Test plan document (`tests/evaluator/test-plan.md`)
- Review report (`review/evaluator/report-2026-05-27T07-08-37.md`)
- Tests: UT-026 (pydantic-ai parts shape), UT-048 (custom env_prefix), UT-049 (empty cli_name rejection), UT-050 (report corrupt JSON), UT-051 (load_or_init corrupt JSON), UT-052 (concurrent results.json append), UT-053 (report happy path), UT-054 (list with valid results), UT-055 (list missing file), UT-056 (WorkSteward parallel execution), UT-057 (config path resolution)

### Changed
- Version bumped from 0.1.9 to 0.1.12a1
- `extract_tool_calls_from_history()` now uses `_extract_tool_names()` (returns list) instead of `_extract_tool_name()` (returned single name or `None`)
- `ValidatorProtocol.validate()` signature extended with optional `trace` parameter; all test validators updated accordingly
- Reporter header format changed from `**Field**: value` to `- **Field**: value` for consistent markdown list rendering
- README updated with `TrialTrace` usage examples and Stability section documentation
