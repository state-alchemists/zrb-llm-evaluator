## 0.1.1 — 2026-05-20

### Added
- Core experiment runner framework (`runner.py`) — async subprocess orchestration that runs N models × M test cases × T trials as a flat grid with configurable parallelism via `asyncio.Semaphore`
- CLI entry point (`cli.py`) with three commands via Typer:
  - `run` — execute a full experiment with `--models`, `--test-cases`, `--trials`, `--parallelism`, `--timeout`, `--cli-name`, `--output-dir` options
  - `list` — display completed trials from a previous experiment
  - `report` — re-generate the Markdown report from an existing `results.json`
- Test case loader (`loader.py`) — discovers test cases from directories, imports `validator.py` modules, validates protocol conformance at load time via `isinstance` against `@runtime_checkable` protocol
- Pluggable validator protocol (`protocols.py`) — `ValidatorProtocol` with a `validate(output_dir, log_content) -> ValidationResult` signature
- Data models (`models.py`):
  - `Experiment` — envelope with `id`, `config`, `started_at`, `completed_at`, `results`
  - `ExperimentConfig` — model list, test case paths, trial count, parallelism, timeout, CLI name, output directory
  - `TrialResult` — per-trial outcome with model, test case, trial index, status, score, duration, exit code, token counts, tool call counts, log paths, and verification result
  - `ValidationResult` — status (`EXCELLENT`/`PASS`/`FAIL`), score (0.0–1.0), and per-check breakdown
  - `ValidationCheck` — individual check with name, passed flag, and message
  - `Report` — aggregated report with summary statistics
- Cost parser (`cost_parser.py`) — extracts cost summary lines from `zrb` subprocess output and counts tool calls from LLM history JSON files
- Reporter (`reporter.py`) — generates human-readable Markdown reports and structured JSON output with atomic file writes (temp file + `os.replace`)
- Resume support (`ResumeManager`) — loads existing `results.json`, skips cells with terminal statuses, persists results atomically after each trial
- Experiment envelope persistence — `experiment.json` written alongside `results.json`; preserves `id` and `started_at` across resume runs
- Trial directory isolation — each trial gets `{output}/{model_safe}/{test_case}/trial-{N}/` with its own `stdout.log` and `history/` directory
- Test case workdir staging — optional `workdir/` subdirectory content is copied into each trial's working directory for scaffolding files
- Per-trial timeout handling — kills subprocess after configured timeout, preserves partial output, records `exit_code=-1`
- Comprehensive test suite (46 test files):
  - Unit tests for runner, models, CLI, resume, semaphore, session naming, tool call parsing, validator protocol
  - Integration tests covering full experiment lifecycle
  - Test for ensuring no `zrb` import at module level (`test_no_zrb_import.py`)
- Documentation:
  - `README.md` — quick start, feature list, installation, usage guide, CLI reference, architecture overview, output structure, development instructions
  - `docs/architecture.md` — four-layer architecture description
  - `docs/adr/ADR-1.md` through `ADR-6.md` — architecture decision records
  - `docs/product.md`, `docs/tech.md`, `docs/test-strategy.md`
  - `specs/experiment-runner/requirements.md` and `design.md`
  - `requirements/problem-brief.md` and `entity-dictionary.md`
  - `AGENTS.md` and `.sdlc/rules.md`
- Project configuration:
  - `pyproject.toml` — Poetry project with dependencies (pydantic, typer, rich), dev dependencies (pytest, pytest-asyncio, pytest-mock, ruff, mypy), CLI script entry point, Ruff and mypy settings
  - `poetry.toml` — Poetry local config
  - `.gitignore`

### Changed
- Renamed trial log file from `chat.log` to `stdout.log` for clarity
- Switched from `os.rename` to `os.replace` for atomic file writes (cross-platform compatibility)
- Updated `run_experiment` return type from `list[TrialResult]` to `Experiment` envelope, adding `experiment.json` persistence
- Improved type annotations in `ResumeManager` (`list[dict]` → `list[dict[str, object]]`)

### Fixed
- Missing workdir staging — test case `workdir/` content is now copied into each trial's working directory so the LLM sees scaffolding files during execution
- Stale trial directories from prior incomplete runs are now cleaned (`shutil.rmtree`) before retry, preventing overlay onto stale LLM artifacts
- Removed unused `TYPE_CHECKING`-guarded import of `ValidatorProtocol` in runner

### Removed
- `__pycache__` directories from version control
