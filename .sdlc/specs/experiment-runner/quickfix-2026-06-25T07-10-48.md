# Quickfix: Remove deprecated EARS dialect from spec.md (comment sanitization + REQ-007 body fix)

**Date**: 2026-06-25
**Feature**: experiment-runner  **Key**: EXPERIMENT-RUNNER
**Trigger**: `sdlc-validate.py` emits 20 EARS dialect warnings against `experiment-runner/spec.md`

## Behaviour Change Summary

No behaviour change. The previous quickfix (`quickfix-2026-06-24T23-43-58`) rewrote requirement bodies
to canonical EARS but left provenance notes in inline HTML comments containing the old text
("was ALWAYS SHALL", "was WHERE…THEN", "was AS…THEN", "was UNLESS…THEN"). The validator's EARS regex
scans the full requirement line including the comment, causing 19 false-positive warnings. Additionally,
REQ-007's body uses the informal English word "unless" mid-sentence, which triggers the UNLESS pattern
on a genuine body match. This quickfix sanitizes the 19 comment texts and rewrites REQ-007 to avoid
the word while preserving identical semantics.

## Requirements Delta

*Use canonical EARS (WHEN / WHILE / WHERE / IF…THEN / ubiquitous SHALL).*

### ADDED
*(none)*

### MODIFIED

- `REQ-007` — was: `WHEN a subprocess returns a non-zero exit code THEN SHALL the trial be recorded as ERROR unless a verification marker overrides it.`
- `REQ-007` — now: `WHEN a subprocess returns a non-zero exit code, the system SHALL record the trial as ERROR; IF a \`VERIFICATION_RESULT:\` marker is present in the subprocess output, THEN the marker's status SHALL supersede the exit-code result.`

**Comment sanitization** (no semantic change, not requirements delta — listed for traceability):
19 requirements (REQ-001, -002, -003, -008, -009, -010, -011, -012, -013, -014, -020, -021, -025,
-026, -027, -028, -029, -030, -034) have their inline comment provenance notes changed from
`"was ALWAYS SHALL"` / `"was WHERE…THEN"` / `"was AS…THEN"` / `"was UNLESS…THEN"` to neutral forms
that do not contain the deprecated keywords, e.g. `"migrated from deprecated ubiquitous form"`.
