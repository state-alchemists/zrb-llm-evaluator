# Quickfix: Match real zrb token-summary format and isolate per-trial LLM journal

**Date**: 2026-05-24
**Feature**: experiment-runner
**Trigger**: Two issues observed in bake-run output. (1) Every `TrialResult` in `results.json` had `total_tokens=input_tokens=output_tokens=cache_read_tokens=0`, even when stdout clearly contained a 💸 usage line — the regex was written against a hypothetical `"Total tokens: X | Input: Y | Output: Z | Cache: W"` format that zrb has never emitted. zrb actually prints `💸 (Requests: N | Tool Calls: M | Total: Z) Input: A | Audio Input: B | Output: C | Audio Output: D | Cache Read: E | Cache Write: F | Details: …` (see `zrb/llm/util/stream_response.py:177-191`). (2) Per-trial isolation is incomplete: `ZRB_LLM_HISTORY_DIR` is set per cell, but `ZRB_LLM_JOURNAL_DIR` (the `llm-notes/` journal — zrb's "External Long-Term Memory") falls back to `~/.zrb/llm-notes/`. Every trial reads/writes the same global journal, so cross-trial state leaks (model A's notes contaminate model B's run), which is exactly the comparison we are trying to avoid.

## Behaviour Change Summary
Before: token fields were silently zero for all trials because `_COST_LINE_PATTERN` never matched real zrb output; `llm-notes/` was global across the whole machine, so trials saw each other's accumulated journal entries. After: `parse_cost_summary` matches the real `💸 (… Total: Z) Input: A | Audio Input: … | Output: C | Audio Output: … | Cache Read: E …` format and populates `total_tokens`, `input_tokens`, `output_tokens`, `cache_read_tokens` correctly (using the LAST 💸 line in stdout — zrb's per-run totals are already cumulative, so summing would double-count); the runner sets `ZRB_LLM_JOURNAL_DIR={cell_dir}/llm-notes/` as a sibling of `workdir/` and `history/`, so each trial gets a fresh, isolated journal.

## Design Impact
| Property | Before | After |
|----------|--------|-------|
| Round-Trip | Token fields serialized as 0 — round-trip still valid but meaningless. | Token fields carry the real LLM-reported counts; round-trip remains lossless. |
| Uniqueness | Trial cells unique by `(model, test_case, trial_index)` — but the shared journal dir leaked state across cells, so observable behaviour was not unique. | Per-cell journal dir makes the runtime state of each cell genuinely independent. |
| Atomicity | N/A — unchanged |
| Validation | N/A — unchanged |
| Idempotency | Partially compromised: a resumed run could see notes written by a previously-completed cell (or a manual `zrb chat` from the user) and behave differently. | Restored: each cell starts with its own empty `llm-notes/`; resume of a still-pending cell wipes and recreates its directory along with the rest of the cell (`runner.py:248-250`). |

Design note (informational, not part of the contract change): the "Per-Trial Filesystem Layout" diagram in `design.md:55-62` should grow one sibling:

```
{output_dir}/{model_safe}/{test_case}/trial-{N}/
├── workdir/         ← subprocess cwd (LLM-visible)
├── stdout.log       ← LLM-invisible (sibling of workdir)
├── history/         ← LLM-invisible — ZRB_LLM_HISTORY_DIR
└── llm-notes/       ← LLM-invisible — ZRB_LLM_JOURNAL_DIR  (NEW)
```

`ZRB_LLM_SNAPSHOT_DIR` is intentionally left unchanged (still falls back to its global default); only the journal is isolated. The new directory lives as a sibling of `workdir/`, preserving REQ-020 / REQ-021 (subprocess cwd remains the nested `workdir/`; new artifacts are siblings, not children).
