# Quickfix: Kill the whole zrb process group on timeout

**Date**: 2026-05-21
**Feature**: experiment-runner
**Trigger**: Observed during bake run — 5-min `--timeout 300` cells stayed alive 45+ minutes. `proc.kill()` only signals the direct child; `zrb chat` descendants (LLM HTTP workers, etc.) survived, held semaphore slots, and drove the TIMEOUT rate to 45%.

## Behaviour Change Summary
Before: on timeout the runner called `proc.kill()`, which sends SIGKILL to the immediate `zrb` child only. Any grandchild processes spawned by `zrb chat` continued to run, sometimes for tens of minutes, holding parallelism slots and skewing TIMEOUT counts. After: the trial subprocess is launched in its own process group (`start_new_session=True`), and on timeout the runner sends SIGKILL to the entire group via `os.killpg`. Descendants are reaped along with the leader, so the cell releases its slot promptly and the TIMEOUT recorded in `results.json` matches reality.

Design note (informational, not part of the contract change): `Error Handling → Subprocess timeout` recovery row in `design.md` continues to describe killing the subprocess; the underlying mechanism is now `os.killpg(os.getpgid(proc.pid), SIGKILL)` against the group started via `start_new_session=True`. This is a POSIX-only mechanism; the project already targets darwin/linux (zrb does not officially ship on Windows).

## Non-Regression Hints
- `UT-005` (`test_timeout_kills_subprocess_and_records`) and `UT-009` (`test_timeout_result_references_log_file`) must continue to pass. They mock `create_subprocess_exec` and assert TIMEOUT status; the new call to `os.killpg` must be patched or the mock proc must expose a real `pid` attribute that survives `os.getpgid` (typically by patching `os.getpgid`/`os.killpg` in the test).
- The `except Exception` block in `TrialRunner.run` (around `runner.py:395`) should not start swallowing `ProcessLookupError` from killpg; the killpg call belongs inside the TimeoutError branch, narrowly guarded.
- Manual verification on the next bake run: launch with a deliberately small `--timeout` (e.g. 30s) against a test case that fans out subprocesses; confirm via `ps -eo pid,ppid,pgid,comm | grep zrb` that no zrb descendants linger after the parent runner has logged DONE for that cell.
