# Quickfix: Canonical EARS restatement, REQ-030–034 traceability tags, and UT-048–057 test-plan entries

**Date**: 2026-06-24
**Feature**: experiment-runner  **Key**: EXPERIMENT-RUNNER
**Trigger**: /sdlc-migrate surfaced deprecated EARS dialect (28 warnings) and 20 traceability errors after feature-key re-keying. All requirements are already implemented; only spec text and comment tags are stale.

## Behaviour Change Summary
No behaviour changes. The system already implements REQ-001 through REQ-034 and the tests UT-048–057 already exist. This quickfix (1) restates deprecated EARS dialect in canonical form — `ALWAYS SHALL` → ubiquitous, `AS…THEN` / `UNLESS…THEN` / old `WHERE <state>` → `IF…THEN` or `WHILE` as appropriate — without altering requirement meaning; (2) adds missing `@sdlc EXPERIMENT-RUNNER:REQ-030/031/032/033/034` inline tags and updates `IMPLEMENTS:` headers in three source files; and (3) registers UT-048–057 in the test plan.

### MODIFIED (EARS restatement — meaning unchanged)

- `REQ-001` — was: `ALWAYS SHALL each trial generate a unique session name that survives timeout.`
- `REQ-001` — now: `Each trial SHALL generate a unique session name derived from its model identifier, test case name, and trial index, using a form that survives timeout.`

- `REQ-002` — was: `ALWAYS SHALL the number of concurrent subprocesses not exceed the configured parallelism.`
- `REQ-002` — now: `The runner SHALL limit concurrent subprocess execution to the configured parallelism value using an asyncio.Semaphore.`

- `REQ-003` — was: `ALWAYS SHALL completed trial results persist to disk before the next trial begins.`
- `REQ-003` — now: `Each completed trial result SHALL persist to disk before the next trial begins.`

- `REQ-008` — was: `WHERE a trial is in TIMEOUT or ERROR state THEN SHALL the partial LLM history file on disk still be referenced in the result.`
- `REQ-008` — now: `WHILE a trial is in TIMEOUT or ERROR state, the partial LLM history file on disk SHALL still be referenced in the result.`

- `REQ-009` — was: `WHERE a trial completed with a valid output THEN SHALL the test case's validator be invoked with the output directory and log content.`
- `REQ-009` — now: `WHEN a trial completes with a valid output, the system SHALL invoke the test case's validator with the output directory and log content.`

- `REQ-010` — was: `AS parallelism is greater than 1 THEN SHALL trials be dispatched across concurrent async tasks gated by a semaphore.`
- `REQ-010` — now: `WHEN parallelism is configured above 1, the system SHALL dispatch trials across concurrent async tasks gated by a semaphore.`

- `REQ-011` — was: `AS a validator raises an exception THEN SHALL the trial be recorded as ERROR with the exception message in details.`
- `REQ-011` — now: `IF a validator raises an exception, THEN the system SHALL record the trial as ERROR with the exception message in details.`

- `REQ-012` — was: `AS --cli-name is provided THEN SHALL the runner invoke that binary instead of zrb.`
- `REQ-012` — now: `WHEN --cli-name is provided, the system SHALL invoke that binary instead of zrb.`

- `REQ-013` — was: `UNLESS a test case directory contains a valid validator module THEN SHALL the runner reject that test case with a clear error message.`
- `REQ-013` — now: `IF a test case directory does not contain a valid validator module, THEN the system SHALL reject that test case with a clear error message before any trial begins.`

- `REQ-014` — was: `UNLESS all required arguments (models, test-cases, trials) are provided THEN SHALL the CLI print usage and exit non-zero.`
- `REQ-014` — now: `IF any required argument (models, test-cases, trials) is absent, THEN the CLI SHALL print usage and exit non-zero.`

- `REQ-020` — was: `ALWAYS SHALL the trial subprocess cwd be a nested workdir/ directory inside the per-trial cell directory — never the cell directory itself.`
- `REQ-020` — now: `The trial subprocess cwd SHALL be a nested workdir/ directory inside the per-trial cell directory — never the cell directory itself.`

- `REQ-021` — was: `ALWAYS SHALL the trial's stdout.log, history/ directory, notes/ directory, and any other evaluation artifacts live as siblings of workdir/ and not inside it.`
- `REQ-021` — now: `The trial's stdout.log, history/ directory, notes/ directory, and any other evaluation artifacts SHALL live as siblings of workdir/ and not inside it.`

- `REQ-022` — was: `WHEN a test case has no dedicated workdir/ source to stage THEN SHALL the runner create an empty workdir/ directory inside the trial cell before launching the subprocess.`
- `REQ-022` — now (EARS already canonical, keep as-is): no change.

- `REQ-025` — was: `ALWAYS SHALL trial rows in report.md be sorted by model ascending, then test_case ascending, then trial_index ascending.`
- `REQ-025` — now: `Trial rows in report.md SHALL be sorted by model ascending, then test_case ascending, then trial_index ascending.`

- `REQ-026` — was: `ALWAYS SHALL the best-metric bolding scope be one test case (spanning all models and all trials in that test case), and ALWAYS SHALL trials with status FAIL, TIMEOUT, or ERROR be excluded from the best-metric computation.`
- `REQ-026` — now: `The best-metric bolding scope SHALL be one test case (spanning all models and all trials in that test case), and trials with status FAIL, TIMEOUT, or ERROR SHALL be excluded from the best-metric computation.`

- `REQ-027` — was: `ALWAYS SHALL report.md use pure Markdown syntax — no embedded HTML — for sort order, bolding, and status icons.`
- `REQ-027` — now: `report.md SHALL use pure Markdown syntax — no embedded HTML — for sort order, bolding, and status icons.`

- `REQ-028` — was: `WHERE a trial with status PASS or EXCELLENT ties or sets the best value within its test case for any of (duration min, score max, total_tokens min, tool_call_count min) THEN SHALL the corresponding metric cell in report.md be wrapped in Markdown bold (**…**).`
- `REQ-028` — now: `WHEN a trial with status PASS or EXCELLENT ties or sets the best value within its test case for any metric (duration min, score max, total_tokens min, tool_call_count min), the system SHALL wrap the corresponding metric cell in report.md in Markdown bold (**…**).`

- `REQ-029` — was: `AS a trial's status is rendered in report.md THEN SHALL the status text be prefixed with the icon mapping: EXCELLENT → 👍, PASS → ✅, FAIL → ❌, TIMEOUT → ⏱️, ERROR → ⚠️.`
- `REQ-029` — now: `WHEN a trial's status is rendered in report.md, the system SHALL prefix the status text with the icon mapping: EXCELLENT → 👍, PASS → ✅, FAIL → ❌, TIMEOUT → ⏱️, ERROR → ⚠️.`

- `REQ-030` — was: `ALWAYS SHALL the Experiment.id and started_at be preserved across resumed invocations, even though the persisted config is replaced by the current CLI invocation (CLI args are authoritative).`
- `REQ-030` — now: `The system SHALL preserve Experiment.id and started_at across resumed invocations, even though the persisted config is replaced by the current CLI invocation (CLI args are authoritative).`
